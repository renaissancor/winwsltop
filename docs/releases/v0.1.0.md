First public release: a read-only terminal monitor for one Windows PC running WSL2, showing who is using the shared GPU.

## What's in it

- Overall, GPU and CPU panels on keys `1`, `2` and `3`, with one-minute graphs.
- GPU use by Windows process and for the WSL VM as one figure, plus device utilisation, memory, power, temperature and clock.
- `/dev/dxg` holders in WSL: who has the GPU open, not how much they use.
- CPU, memory, disk and network for Windows, and CPU and processes for WSL.
- `--text`, `--once` and `--record N` for one frame or a JSON record, documented in `docs/json-output.md` so scripts and AI agents can use it unattended.

## Get it

Download `winwsltop.exe` and run it in Windows Terminal. There's no installer and it doesn't need administrator rights. WSL2 with `python3` 3.8 or later supplies the Linux side, and the collector is built into the `.exe`.

The binary isn't code-signed, so SmartScreen may warn you. Check it against `winwsltop.exe.sha256`.

## Known limits

- Tested on one machine: Windows build 26200, WSL2 kernel 6.6.114.1, NVIDIA RTX 4070. AMD and Intel GPUs, other distros, Windows 10 and the legacy console are untested.
- The Windows-versus-WSL split is at VM level, with one trial per case. Per-Linux-process GPU use is not measured.
- Running it starts the WSL distro if it was stopped.
- A few failed reads can still show as 0: see `docs/TODO.md` items 22 and 24.
- The WSL graph can show a gap of about 2 s on a healthy collector, when the two one-second loops slip against each other.
- `q` is unproven under a Korean IME in Hangul mode. Ctrl+C always quits.
