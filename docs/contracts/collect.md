# Contract: collect

Owner: the `collect` role. Paths: the `collect` row of [`../ARCHITECTURE.md`](../ARCHITECTURE.md).

## Purpose

Fill the snapshot with measured values from both sides: Windows through its native APIs and PDH, the
WSL guest through a Python collector that reads `/proc` and sends one JSON line a second over a pipe.

## What belongs here

- `src/host/`: CPU, memory, disk, network and processes on Windows. Also the VM view: `vmmemWSL` and
  its parent `vmwp.exe`, found by name in the process list.
- `src/gpu/`: the NVML device reading, the `GPU Engine` counters, the `GPU Process Memory` counters.
- `src/wsl/`: the bridge that starts `wsl.exe`, feeds it `collector.py`, keeps the latest line and
  estimates the clock offset; `collector_embed.cpp`, generated by `wsl-collector/embed.py`.
- `wsl-collector/collector.py`: the Linux half. Stdlib only, Python 3.8+, never installed.

## What does not belong here

- A new snapshot field or a new protocol field. Request it from core.
- Any inference about which side is using the GPU. That is `src/analysis/`, owned by core.
- Drawing or formatting.
- Writing anything inside WSL, reading a command line, or touching a process.

## Rules

1. A counter is read only after `docs/measurable.md` records it as observed on this machine. The
   source comment names the ledger section.
2. A value that cannot be read is absent, not zero and not the previous value. `gpu_device_view.has_*`
   is the pattern, and every `sample()` resets its output before any early return.
3. Windows and WSL numbers are never combined in a collector.
4. PID is not identity. Windows rows are keyed by PID and create time, Linux rows by PID and start
   time, because PIDs are reused.
5. After editing `collector.py`, run `python3 wsl-collector/embed.py` in the same commit.
   `scripts/check.sh` fails otherwise.
6. The bootstrap and the collector read stdin and write stdout only; stderr goes to `NUL`. Nothing
   outlives `winwsltop.exe`: the job object kills `wsl.exe`, and stdin EOF ends the collector.
7. Per-Linux-process GPU use is not measured and is never emitted as if it were. `/dev/dxg` holders are
   identity only.

## How to validate

- `scripts/check.sh` (embedded copy in sync) and `scripts/check.sh --windows` (it compiles).
- `winwsltop --once` against Windows' own figures, as in the ledger section "Windows collector checked
  against Windows". The acceptable gap is what that section shows: counts equal, rates within a window.
- `scripts/build.sh wsl-collector/clock_probe.cpp`, then `clock_probe.exe 25`: offset known within the
  first second, round trip in the low milliseconds, drift reported after 5 samples and 3 s.
- Kill the collector's `python3` inside WSL while `winwsltop` runs: a new line within about 3 s and
  `restarts` incremented (ledger, "WSL collector checked").
- GPU readings against `nvidia-smi` and `Get-Counter`, as `experiments/02-gpu-device/compare.sh`
  does. No GPU load is needed. A load is started only with the user's go-ahead.

## Open questions

- Why NVML reads 11 to 20 percent utilization at idle while the engine counters sum to about 6
  (ledger, experiment 01 and 02). Different definitions, or a bad reading. Unresolved.
- What the second LUID is. `Win32_VideoController` lists one adapter; PDH shows two (ledger).
- Whether WSL GPU memory appears under `vmwp.exe` under load. Only idle has been seen.
- PROPOSED: a start-failure count or message so an invalid `--distro` or a missing `wsl.exe` is
  visible on the screen (`TODO.md` item 8). Needs a snapshot field: request to core.
- Machines with more than 64 logical CPUs: the CPU collector covers one processor group and says
  nothing about it (`TODO.md` item 11).
- A reset network counter (`TODO.md` item 6) leaves that rate at 0 for the sample, not absent, because
  `net_row` has no `has_rate`. Rule 2 says absent; a flag would need a snapshot field: request to core
  if the distinction matters on the screen. Added 2026-11-01.

## Decision log

- 2026-10-31. NVML is loaded from `System32` by full path at runtime, so the build needs no SDK and a
  missing driver leaves `present` false (ledger, experiment 02).
- 2026-10-31. Memory uses `nvmlDeviceGetMemoryInfo_v2`, which excludes driver-reserved memory as
  `nvidia-smi` does (ledger, experiment 02).
- 2026-10-31. The distro name is passed to `wsl.exe` unquoted; a quoted name was rejected. Names with
  whitespace or quotes are refused instead.
- 2026-10-31. Clock offset comes from the lowest-round-trip ping in a 30-sample window, carried
  forward at the fitted drift; a wall-clock step of over 50 ms empties the window (`PROTOCOL.md`).
- 2026-11-01. `src/host`, `src/gpu` and `src/wsl` became one area, because one agent can hold all
  three and the GPU can only be exercised by one agent at a time anyway. Approved by the user.
- 2026-11-01. Every `sample()` resets its output before any early return (`TODO.md` item 1). The
  priming call of cpu, processes and network returns false with empty output: rows with counts but
  no rates are not reported, so a reader never sees a zero rate that was really unmeasured.
- 2026-11-01. A process with no image name is `Idle` only when its PID is 0; any other is `?`, not an
  empty string, so the row is visibly unnamed (`TODO.md` item 13).
- 2026-11-01. The bridge keeps the child's process handle and terminates it in the destructor as a
  fallback to the job object (`TODO.md` item 3); the clock window is emptied when the child ends, so
  `clock_known` is false during the backoff (item 7); unterminated child output past 1 MiB is dropped
  (item 17); a failed `CreateFileW("NUL")` leaves the child without a stderr handle (item 18).
- 2026-11-01. `collector_embed.cpp` holds `const unsigned char[]`, so a non-ASCII byte in
  `collector.py` compiles (`TODO.md` item 10).
